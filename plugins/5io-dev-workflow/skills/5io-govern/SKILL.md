# 里程碑治理

- 对照现有实现及 CI 检查项目说明、验收记录和验证命令。对重复规则找出适合的单一来源。
- 用只读 Git 信息盘点相关分支与 worktree。区分已合并、有未提交或未推送工作、仍在进行，以及状态待确认的项。注明依据和远端信息是否为现有缓存。
- 给出少量可执行的治理项，标明影响、证据和建议顺序。重复出现的问题优先考虑明确约定或现有 CI 可执行的检查。
- 按已经授权的范围修订文件。合并、移除 worktree 或删除分支前核实归属、未提交工作和合并状态，并遵守任务授权。

## 从三类证据开始

| 核对项 | 看什么 | 怎样判断 |
| --- | --- | --- |
| 项目约定 | 根目录和模块规则、方案、文档链接 | 对照入口和 CI。指向已删除文件或失效命令时记下证据 |
| 验收记录 | 相关快测、集成检查、人工验证和交付记录 | 先找漏验的关键行为。区分命令存在、实际跑过和结果可复核 |
| 分支与 worktree | 当前提交、上游状态、工作目录和各自的未提交改动 | 相同提交仍可能有本地改动。审查前逐个 worktree 查状态 |

合并状态相对于明确的目标分支核验。遇到 squash 或 rebase，提交不在祖先链上时再查 PR、实际变更或其他可靠线索，保留待确认状态。没有刷新远端引用时标明证据时间与局限。

## 交付清单

- 文档与规则：路径、失效或重复的具体条目、建议保留的来源。
- 验收欠账：受影响行为、缺失证据、需要谁验证。
- 工作项：分支、worktree、当前状态、依据与下一步。对仍有未提交、未推送或归属不明的工作标记为待处理。
- 修订范围：可在本轮修正且已授权的项目，以及需要决定的事项。完成后复查受影响链接或命令。
