# 根因排错

1. 记录预期、实际现象、环境和最小触发条件。能复现时保留失败输出或测试。无法复现时给出观察证据、已排除假设和下一条最有区分力的检查。
2. 从错误结果回溯到状态首次出错的边界。按证据选择对照实验、日志、调用链或提交对比。区分触发条件和根因。
3. 只有在修复获授权时改代码。尽量在错误状态产生处修复。发现同类路径时判断是否共因，按任务范围处理。
4. 复跑原场景和相关快测。已有测试无法捕获关键回归时补一个针对性测试。汇报证据、修复位置和未验证项。

## 选择诊断路径

| 现象 | 下一步 |
| --- | --- |
| 稳定复现 | 把输入缩到最小，记录预期、实际和第一个可观察偏差 |
| 已知好坏版本 | 比较影响链上的提交，只有复现稳定且命令可重复时才考虑二分 |
| 偶发或环境相关 | 固定版本、配置、输入与时序，逐次改变一个变量，记录出现频率 |
| 本机无法复现 | 列明已排除的假设与缺失证据，给出一项最能区分候选原因的检查 |

先理清数据什么时候变错，再选择修改位置。日志显示页面数值少一项时，核对查询结果、过滤条件、聚合输入再到渲染值。比如 `filter(Boolean)` 把合法零值丢弃了，应先核对它与其他调用方的契约，避免在展示层补回一个猜测的数量。

## 收尾标准

- 记录修复前失败、修复后通过及相关快测。无法补自动用例时，说明可复跑的人工检查。
- 同模式别处是否也会出错要用调用链证实。超出允许范围的同类问题单列。
- 移除本次临时诊断；保留能抓住回归的检查。证据仍无法定位根因时，交付已验证事实、候选假设和下一步取证。
