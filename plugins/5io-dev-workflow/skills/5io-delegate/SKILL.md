# 任务交接

交接单包括目标、方案路径及版本、基线、改动边界、必复用入口、验收场景和要求回报的证据。不确定项标记为待核实。

- 实现任务需要共享仓库时，先确认接收方能看到方案和目标快照。并行写入分配独立 worktree 和清晰的路径责任。
- 探索和审查任务使用只读契约。独立审查交接方案、基线与 diff，省略原实现过程中的说服性说明。
- 宿主有原生委派能力且获授权时可直接使用。否则交付可粘贴到新聊天的交接单。模型按项目约定与宿主可用性选择。
- 收到结果后核对实际 diff、验证输出与未完成项。需要整合时检查重叠变更并按目标仓库流程进行。

交接本身不授予执行外部命令、推送或合并的权限。

## 选执行方式

| 任务 | 执行方式 | 交接重点 |
| --- | --- | --- |
| 多模块取证 | 宿主支持时可拆成独立只读子任务 | 每个接收方只交付证据、结论和未知项 |
| 单条实现 | 当前会话或独立会话 | 方案版本、改动范围、验证命令 |
| 多条并行实现 | 明确独立目录或分支责任后使用 worktree | 基线一致，分别记录提交、依赖与交叠风险 |
| 独立审查 | 独立只读上下文 | 方案、基线和待审版本，以及允许核查的证据 |

并行工作若共享接口，先约定接口形状与集成顺序。独立 worktree 只隔离文件写入，接口取舍仍需要统一。确认方案和未提交内容在接收方实际可见，不能访问的资料写明获取方式。

## 可复制交接单

- 目标与角色：探索、实现或审查，说明完成条件。
- 取件方式：仓库、分支或提交 SHA，方案路径及版本，待审版本（如适用）。
- 范围与约束：可改路径、已有复用点、需停下来确认的变化。
- 验收：命令、工作目录、场景、预期结果及必须手工核查的内容。
- 回报：变更文件或提交、实际验证结果、未知项和阻塞原因。

结果缺少证据时先请求补证。遇到路径交叠或基线漂移，先核对两边 diff 与预期行为，再继续整合。没有可用的委派入口时，交付上述交接单即完成此轮任务。
