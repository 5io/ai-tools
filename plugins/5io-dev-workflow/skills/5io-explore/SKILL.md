# 只读探索

1. 阅读适用的仓库约定，由实际入口向下跟到关键状态或数据边界。按任务范围取证。
2. 查找同类实现、调用方和测试。区分已确认可复用的实现与需要验证的候选项。
3. 从项目配置、CI 或文档核实最小验证命令及其工作目录。
4. 交付关键路径、复用点、影响范围、验证入口和待核实事项。给关键结论附文件和行号。

保持只读。并行探索只有在可拆成独立问题、且宿主及用户授权允许时才使用。

## 按问题选择深度

| 情况 | 从哪里查 | 何时够用 |
| --- | --- | --- |
| 查入口或复用点 | 从调用方、注册表、路由或命令定义找真实入口 | 找到一个能解释当前行为的入口、可复用实现和验证入口 |
| 跨模块行为 | 沿调用链追到状态变化、持久化或外部边界，再回查调用方 | 能说明每个受影响模块的责任及行为变化 |
| 多入口或症状不一致 | 对照客户端、后台任务、旧版本或配置分支，标明哪个路径能触发 | 已解释关键分支差异，剩余未知项有明确取证办法 |

同名文件或函数只算线索。查看实际注册、导入、配置或测试，确认它是否进入当前运行路径。检查复用候选的输入、生命周期和副作用。例如两个导出流程共用编码器，也可能有不同的取消语义。

## 交付格式

- 入口与调用链：每一跳给出路径或符号，标明状态、数据或控制如何传递。
- 可复用点：写清可直接使用的能力、使用约束和需验证之处。
- 影响面：列出直接调用方、相关配置及现有测试。
- 验证：写出命令、工作目录、前置条件。区分从仓库核实的命令和实际执行过的命令。
- 未知项：给出影响和下一条检查。入口无法查实或环境不可用时，保留已证实部分。
