# 人话方案

在支持仓库读取的助手中粘贴下方提示词。有规划模式时可以选用。替换方括号，缺少的可选信息可以删掉。

~~~text
我想在当前仓库实现【功能或行为变化】。背景是【谁遇到什么问题】。已知约束或参考是【可改范围、已有决定、参考文件，可选】。

这一轮先只读探索并写方案。请查看适用的 AGENTS.md，核对真实入口、调用链、可复用实现和现有验证命令。对尚未查实的行为或路径，明确标为待核实。等我确认方案后再改文件。

用产品和工程都能看懂的语言讲清四件事：

1. 用户怎么用。按实际操作顺序说明入口、默认状态、操作后的反馈和必要的失败或恢复路径。适用于界面的需求，写清界面会怎么变。
2. 大概怎么做。说明会改哪几个模块、复用什么、哪些已有行为需要保持。列出预计改动范围和本次不包含的工作。给关键判断附上仓库路径，省略实现代码。
3. 特殊情况和取舍。只列和本次有关的边界场景。只有会改变交互、数据兼容性或交付范围的决定需要我确认，给出你的建议和理由。其余可逆细节按仓库惯例处理，并写明有影响的假设。
4. 怎么验收。给出可复跑的场景，写清前置条件、操作和预期结果。列出已核实的快测或检查命令，以及需要人工验证的行为。

结尾列出待我决定的事项。如没有，直接给出可以交给实现会话的方案。需要跨会话时附 Git 基线、仓库相对的可改路径和验收编号，并分别写出局部快测与合并检查的命令和工作目录。交接时用完整提交 SHA 加仓库相对路径标识获批方案和范围 JSON，或独立提供可信快照。
~~~
